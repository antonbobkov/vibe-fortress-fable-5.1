# T-332 — Render goldens: assertions about meaning in place of full screens

**Source:** the process review, [`../../reports/audits/2026-10-15-process-review.md`](../../reports/audits/2026-10-15-process-review.md) · **Size:** M · **Needs:** — · **Status:** open; after the UI batch in worktree `codexa` (the same tests)

## Why

Two fifths of the UI tasks since 2026-10-11 moved a render golden, regenerated by the agent that changed the screen, so the golden shows a change and not that the screen is right (process review § 2).

## What to do

- List each render golden case in `test/golden/render/` and what it is the only test of.
- Where a golden is the only test of a screen or panel's content, add assertions about meaning (this row says X, the key hint names Y, the warning appears) in a unit test, then drop the golden case. Keep a small set of full-screen goldens as layout smoke tests: one per screen at the default size and one at 80 columns.
- No behaviour change: every new assertion passes on the current code.

## Done

- Each remaining golden case is a layout smoke test, named as such in `testing-strategy.md` § Golden tests.
- Each dropped case is replaced by meaning assertions that pass.

## Performance

Measured by hand in the test environment (Node 24, Windows, Vitest) for this report; no budget
applies at M2 (the performance smoke runs at M3, M6 and M8), and nothing in the gate failed on
these numbers, so the connectivity code is unchanged.

| Measure | Time |
|---|---|
| Full connectivity rebuild (`rebuildAll`, all 5 movement classes), standard 96×96 `flat-test` map | 290–293 ms |
| Relabel after one dirtied chunk (`rebuildDirty`, 1 chunk; the global relabel runs for all 5 classes) | 45–46 ms |
| 1,000 ticks, default party idle, `flat-test` | ~93 ms |
| 5,000 ticks, busy fortress of `core_save_roundtrip` (hauling, building, channels) | ~1.0 s |
| Save of that fortress (all sections, deflate; no thumbnail) | ~24 ms, 12.6 kB |
| Load of that save (inflate, restore, one full relabel) | ~400 ms |

Note for M3: the per-chunk relabel (~46 ms) still exceeds the 50 ms/tick frame budget together
with the rest of a tick whenever a tick changes terrain; the M3 perf smoke (average ≤ 2× budget,
worst tick ≤ 40 ms) will fail on digging-heavy ticks unless the global relabel is made
incremental or limited to the classes a change can affect. Loading spends most of its time in
the one full relabel (~290 ms).

## Performance

Measured by hand in the test environment (Node 24, Windows, Vitest) for this report; no budget
applies at M1 (the performance smoke runs at M3, M6 and M8), and nothing in the gate failed on
these numbers, so the M0 connectivity code is unchanged.

| Measure | Time |
|---|---|
| Full connectivity rebuild (`rebuildAll`, all 5 movement classes), standard 96×96 `flat-test` map | 316–320 ms |
| Relabel after one dirtied chunk (`rebuildDirty`, 1 chunk; the global relabel runs for all 5 classes) | 52–59 ms |
| Generated local map (`test-1`, default region) + world + first labels + arrival | ~920 ms |
| 1,000 ticks, default party idle, `flat-test` | ~14 ms |
| 1,000 ticks, default party idle, generated `test-1` | ~19 ms |
| E2E `designate-by-drag`: 3,000 ticks at 4× with a 12-tile dig (each dug tile relabels a chunk) | 40 s wall, 37.5 s of it the 4× clock |

Note for later milestones: the per-chunk relabel cost (~50 ms) exceeds the 50 ms/tick frame at
20 ticks/s whenever a tick changes terrain; the M3 perf smoke (average ≤ 2× budget, worst tick
≤ 40 ms) will fail on digging-heavy ticks unless the global relabel is made incremental or limited
to the classes a change can affect.

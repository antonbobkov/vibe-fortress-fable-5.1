### Connectivity relabel (the M2 gate's open issue)

The M2 report noted that the global relabel would break the M3 budgets. `perf: incremental
connectivity relabel (T-M3-09)` (DECISIONS.md D-100) made it exact and cheap; the same runs with
the previous implementation are in the "before" column.

| Measure | Before | Now |
|---|---|---|
| Full rebuild (`rebuildAll`, 5 classes, standard 96 × 96 × 48 map) | 330 ms | 44 ms |
| Relabel after one dirtied surface chunk | 57 ms (45–63) | 0.7 ms |
| `fl_perf` pathing average | 15.77 ms | 1.07 ms |
| `fl_perf` average tick | 16.83 ms | 2.11 ms |
| `fl_perf` worst tick | 52.08 ms | 15.33 ms |
| Generated river (inflowing brook), connectivity per tick | 10.73 ms (34.7 worst) | 0.13 ms (0.8 worst) |
| Disturbed cavern lake (4,387 active tiles), connectivity per tick | 29.55 ms (71.5 worst) | 4.51 ms (13.0 worst) |

The labels are unchanged: they still equal BFS reachability, and a full rebuild (what a load does)
gives the same values as the incremental one, which `test/property/connectivity-incremental.test.ts`
checks for all five movement classes.
